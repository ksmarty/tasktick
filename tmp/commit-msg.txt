Name the session cookie per request, and read it back the same way

`useSecureCookies` was decided once from `APP_URL`, so a server configured for
https but reached over http answered a sign-in with a `Secure` cookie the
browser silently discarded: the form said it worked, and the next page was
anonymous. The flag now follows the request (`X-Forwarded-Proto`, then the
URL's own scheme, then `APP_URL`), and the app keeps one auth instance per
cookie scheme so the two cannot overwrite each other's cache.

Reading had the same blind spot: `Secure` lives in the cookie's name
(`__Secure-<prefix>.session_token`), so a request carrying the bare name can
never be verified by the instance built for https — it looked for a cookie that
was not there and reported "signed out". Session reads now pick the twin that
matches the name that arrived.

The sign-in page also says what happened when it is handed a cookie it cannot
verify, so a discarded cookie reads as an explanation instead of a loop.
